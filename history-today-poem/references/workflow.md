# 完整 SOP · 历史上的今天 · 一首古诗（明天稿）

无人值守定时任务与手工补做都按这个走。文字风格与真实性底线见 `references/writing-rules.md`；选题的配额、轮换、打分与台账见 `references/selection-framework.md`。

**每天出 3 篇（3 个事件、3 首诗），进草稿箱，绝不自动发布。** 三篇分别落盘为 `<发布日>.json`、`<发布日>-2.json`、`<发布日>-3.json`，三份都写完后跑一次脚本出图建草稿（脚本自动读全部三份）。

## 0. 确认目标日

- 取**北京时间（UTC+8）的「明天」**，记为 `TARGET`。脚本不传 `--date` 时自动算这个值，Agent 侧要自己确认一遍，两边对齐。
- 查的是「历史上的 {TARGET 的月日}」发生的事；数据文件名、正文的日期行、封面日期按 TARGET。
- **`event.date` 必填**，是事件实际发生的完整公历日期，**月日必须等于 TARGET 的月日**；它只进台账与日志，**不进标题**。中国古代稿用 `event.date_label` 写农历/年号，`event.date` 仍填换算后的公历日期。
- **文章标题、正文标题行、封面主标题统一「历史上的今天 | {事件标题}」**，标题里不出现发生日期。
- **正文顶部只有一行日期**：`公历 · 星期 · 农历 · 节气`，农历排在星期后面，由脚本用 cnlunar 换算，不用写进 JSON。**正文没有栏目名行。**
- 任务跨零点这种极端情况：重新确认 TARGET，别沿用开跑时算的日期。

## 1. 先算配额，再读避重清单

1. 在 ROOT 下跑 `python history_post.py --quota`，读输出的 `week`、`region`、`pool`、`mood`、`recent_devices`、`recent_events`、`recent_poems`、`advice`。这一步给出「本周中国 / 国际还差几篇」「哪些池子与气质空着」「最近用过什么笔法 / 事件 / 诗」。每天要做 3 篇，候选要一次备够量。
2. 再读 `data/history/` 最近 7~14 天的 JSON、`data/legacy/`（旧项目搬来的旧格式稿，只取 `event.title` 与 `poem.title` 做黑名单）以及定时任务的执行记忆（若有），补上写过的事件与用过的诗。
3. 台账或 JSON 读不到就如实说明，不要凭记忆编一份清单。相邻两天不重题材池、气质和笔法；别连着几天都选战争、灾难、签条约这类同气质题材。

## 2. 选题与核对

1. 联网搜「历史上的今天 X月X日」，列 **6~10 个候选**（每天 3 篇，候选要够量），先过 `selection-framework.md` 的**四道硬门槛**和**生卒类否决**（单纯「某某出生/逝世」直接不进候选）：日期确凿、来源够、安全、配得上诗。
2. **优先中国相关的事件**：每天 3 篇、每周约 15 篇中国 + 6 篇国际（保持 5:2），按周算缺口，不按天硬切。中国近现代**非政治性**题材（铁路、报刊、大学、考古、工程）正常选；政治敏感、定性争议、主权表述有争议的一律不碰；**单纯的人物生卒类事件否决**。
3. **挑有意义但大众不太关注的小事件**：不追年年被转发的大事和课本里讲烂的题，也不选没分量的冷知识——要有具体的人、具体的动作、具体的一天，读者读完能记住一件事。
4. **读者新鲜度优先**：挑读者多半不知道、但确实有据的事。
5. 至少 **2~3 个来源**交叉核对年份、人物、地点、过程、数字和事件发生的完整年月日。不用存疑、传说、单一来源的说法。
6. 按 `selection-framework.md` 的 5 项打分（各 0~2 分）：新鲜度、可展开、画面、配诗空间、来源质量。**合计低于 6 分就换题，宁可今天不出稿**；同分优先补配额缺口、优先冷门。脚本 `validate()` 会挡下低分稿，不要改校验绕过。
7. **标题要落到大众熟知的符号上**：能写「米老鼠第一次亮相」就不要写「《威利号汽船》首映」，能写「第一封电子邮件发出」就不要写「ARPANET 节点间传输实验」。符号必须准确对得上这件事实，不能为通俗而写错；实在没有通俗说法，就用平实的一句话陈述。
8. 有对不上的地方就换题；仍不行就中止告警，宁可今天不出稿。

## 3. 写作

- `event.date`：事件实际发生的完整公历日期 `YYYY-MM-DD`，月日 = TARGET 的月日。
- `event.date_label` / `event.lunar_md`：中国古代农历稿可选，见第 2 步。
- `event.title`：平实陈述，**优先用大众熟知的符号/俗称**，不堆术语。
- `event.summary`：200 字上下，只写核实过的事实；不写评价与抒情。详见 `writing-rules.md` 第一节。
- `event.sources`：2~4 条 `name` + `url`。第一条带 http 的链接会成为公众号「阅读原文」地址，文末来源小字最多 6 行。
- `selection`：**必填**，见第 6 步。
- 正文不写「历史意义或影响」「赏析」「名词解释」，JSON 里也不要 `event.impact`、`poem.interpretation`、`poem.words` 这三个字段。

## 4. 配诗

- 提炼 3~6 个意境词 → `python history_post.py --suggest "词1,词2,词3" --limit 12` → 挑情绪最贴的一首。
- 联网核实诗题、作者、朝代与**每一句原文**；异文按权威通行本整首定稿。
- 不写 `link`、不写 `poem_note`、不做诗与事件的比附。

## 5. 写诗的背景

只写 `poem.background`（背景，100~180 字），对应正文「背景」一节。要求见 `writing-rules.md` 第三节：只讲诗本身，典故、生平都要准确，不确定的不写。不写赏析、名词解释。

## 6. 落盘 JSON

写入 `data/history/<TARGET>.json`、`<TARGET>-2.json`、`<TARGET>-3.json`（每天 3 篇，一篇一个文件）。基准格式 `data/history/_sample.json`（里面的 `_note` 只是说明，不必写）。

- `date` = TARGET；**不要写 `title` 字段**，文章标题由脚本生成。
- `event.date` **必填**，月日与 TARGET 一致；不要只写 `event.year`。
- `selection` **必填**：`region`（国内/国外）、`pool`（6 池之一）、`mood`（5 气质之一）、`device`（8 笔法之一）、`score`（≥6），可选 `scores` 五项明细（合计须等于 `score`）。枚举见 `selection-framework.md`。
- 段落内换行写成 `\n`，**JSON 必须合法**，写完用 `python -c "import json; ..."` 或脚本的 `validate()` 过一遍。
- `validate()` 查必填字段、日期格式、`event.lunar_md` 换算、选题标签与分数；`run()` 另查事件日期与发布日月日一致。**不做史实与诗句真伪校验**——核实责任在这一步之前。日期行、标题、封面、文末落款都由脚本生成，不用写进 JSON。

## 7. 投递

1. `python history_post.py --dry-run`（一次处理全部数据文件）→ 打开 `output/history/<TARGET>/` 下各篇的 `preview.html` 与 `cover.jpg` 看一眼（第二、三篇在子目录 `2/`、`3/`）：
   - 正文顶部**只有一行**淡灰日期（公历 · 星期 · 农历 · 节气，农历在星期后面），**没有「历史上的今天 · 一首古诗」这行栏目名**；
   - 日期下面是分隔线，再接标题行「**历史上的今天 | 事件**」：「历史上的今天」红色加粗 19px，事件名墨色加粗 19px，两者与诗题同号；
   - 事件部分只有经过（`event.summary`），没有「历史意义或影响」小节；
   - 诗的部分只有「背景」一节，没有赏析、名词解释，也没有「为什么是首诗」；
   - 文末最后一句是「本文由人工策划选题，AI辅助内容生成，再由人工审核润色完成。」；
   - **封面主标题是「历史上的今天 | {事件}」，不出现事件发生日期和重复的农历**；顶部有 TARGET 的农历年月日；主标题没和副标题、底部栏目名重叠；
   - 配图**不偏暗、不阴沉**（脚本会算平均亮度，低于阈值换下一张）。
2. 确认 `output/history/<TARGET>/result.json` 里没有 `draft_media_id`（避免重复稿）。
3. `python history_post.py`（不带 `--date`）→ 出图、上传、建草稿。成功后脚本按发布日写入 `data/selection-log.json` 台账；dry-run 不写。
4. 检查 `result.json` 有 `mode=upload` + `draft_media_id`，`run.log` 无报错，产物齐全。

## 8. 回报格式

中文简报，平实、不写套话，逐篇包含（3 篇各一条）：目标发布日、所选事件（事件日期 + 标题）、配诗（诗名 + 作者，必要时说明异文按哪个通行本定稿）、**选题标签与打分（region / pool / mood / device / score）及本周配额缺口怎么补的**、草稿是否成功（带 `draft_media_id`）、产物路径、有无降级 / 重跑 / 异常。某篇没出稿要说明卡在哪道门槛。

## 9. 已踩过的坑

- **日期与事件对不上**：曾用 11-09 的柏林墙开放，做成 11-13 的稿。现在 `event.date` 必填，且脚本强校验月日与发布日一致；再出现这种错稿会直接报错，不要改代码绕过。
- **农历换算**：农历只改表述，`event.date` 仍须是换算后的公历日期。`event.lunar_md` 与 `event.date` 换算出的农历月日对不上时脚本会报错；换算拿不准就别用农历写法。
- **重复草稿**：同一天 00:08 与 07:00 各投一篇、草稿箱两篇并存。重跑前必查 `result.json`；`draft/add` 每次都是新增，不会覆盖旧草稿。脚本对已有 `draft_media_id` 的稿走 `draft/update` 更新同一份，不新建。
- **选题撞车**：曾连着出现 11-09 柏林墙、11-09 雾月政变、11-10《西线无战事》、11-10《芝麻街》。现在靠 `--quota` 台账 + 黑名单 + 题材池 / 气质 / 笔法轮换，最近几天写过的事件和诗一律不再用。
- **台账污染**：`--dry-run` 不写台账；自测数据别放进 `data/history/20??-??-??.json`，否则会被 `--quota` 当成已选题计数。
- **一天多篇命名**：`<发布日>.json` / `<发布日>-2.json` / `<发布日>-3.json` 是现行标准命名，脚本会全部自动读取。`data/history/2026-11-1x-1/-2/-3.json` 那批旧文件是「每天 3 篇」旧阶段的历史数据，只作黑名单参考，不要改动；新稿按新命名正常写 `-2`/`-3`。
- **史实与异文**：语料里可能是异文（《西塞山怀古》「西晋楼船／枕江流／降旛」、《夜上受降城闻笛》「回乐峰／回乐城」、《泊船瓜洲》「又绿／自绿」），按权威通行本整首定稿，不混拼。
- **配图不贴或太暗**：按 `poem.tags` 取图，可能拿到与意境不搭或偏暗的照片；脚本会按平均亮度筛掉偏暗的候选，仍不合适就改 tags 重跑，不要改图库代码。
- **40164**：出口 IP 不在公众号白名单，与数据源无关，重试无用；白名单支持具体 IP 与 /8、/16、/24 网段。
- **取消任务**：先核实是否已建草稿（查 `result.json`，必要时 `draft/batchget`），再决定要不要撤销；不要凭猜测回报「没发出去」，也不要擅自删草稿。
- **用户否决某天稿件后重做**：把被否决的 `<TARGET>.json`（含 `-2/-3`）移入 `data/legacy/` 归档（标题自动进避重黑名单，重跑不会重选同一题），但 **`output/history/<TARGET>/` 下的 `result.json` 原样保留**——里面有 `draft_media_id`，重跑时脚本会对第一篇走 `draft/update` 更新草稿箱里那份旧稿；删了它就会 `draft/add` 新建，草稿箱里被否决稿与新稿并存。重跑用定时任务工具的 run 触发，并在触发提示里注明「旧稿已否决、勿复用其事件与诗、result.json 保留属预期」，避免后台会话误判为重复稿。
