# 封面设计 · 用户偏好与改版工具

## 用户对封面的要求（常驻标准）

- 原版封面（浅米纸底 + 细字）被用户判为「整体颜色太不显眼、字体不清晰」。
- **配色必须明亮、活泼、有希望感**（朝霞、晨曦、青瓷湖光这类「对新一天的憧憬」方向）；忌灰暗、压抑、大面积灰调底色——第一轮水墨风 A/B/C 变体整体被判「太灰暗」淘汰，不要再出深色水墨风。粉色系也不要。
- 要**有中国文化味道**：保留红印章「诗」、竖排诗句这类元素，但载体换成明快配色；目的是吸引点开阅读、愿意与作者交流。
- 标题字体用**思源宋体加粗（NotoSerifCJK-Bold.ttc，云端已装）+ stroke_width=1 描边**，主标题 44px 起逐档缩小到 ≤2 行；细字淡灰底不再用。
- 改封面这类视觉决策，做 **3~4 个风格变体**发图让用户挑，选中的再固化进 `artwork.py`；不要自作主张直接改正式封面。

## 改稿时的图片交付

- 云端桌面机（root，ssh 终端）的外链图床不可用（tmpfiles 连接重置、0x0 关停、catbox 空响应），不要靠上传图床给用户发图。
- `vision_analyze` 能直接读桌面机的 `/root/...` 路径（ssh 文件系统）自查渲染效果；回复里用 `MEDIA:/root/...` 卡片可把 jpg 发到聊天。文件名含中文也能发；路径写错只报「No such file」，先核对目录再怀疑文件系统。
- 变体脚本落盘位置以脚本里 `OUT` 变量为准（`cover_variants.py` 系列输出到 `ROOT/cover_variants/`，不在 `output/` 下）；自查前先 `ls` 确认实际路径。
- 生成变体后**先自己用 vision_analyze 逐张检查**（文字清晰、无溢出、无压字）再发给用户；带已知小瑕疵可以发，但要在回复里列出「选中后会修」的清单。
- **总览图/索引的版式**（用户明确纠正过）：一图看全部封面的 contact sheet 必须**一行两张、缩略图大**（≥560px 宽，图下带文件名标签），不要 5 列小图——“太花了”就是返回重排的信号；网页索引同样一栏两张（`grid-template-columns:repeat(2,minmax(0,1fr))`），分组用「已入库风格（带意象对照表）/ 迭代过程稿留档」两级。

## 中国画画意的做法（用户最终指的方向）

- 渐变色块 + 几何形状的「设计感」封面被否（渐变山、大圆太阳、扁平波浪逐条被挑）；要做**真画意**：山要「晕」出来但不能晕成一片灰雾。
- 山的画法（`cover_variant_p2.py` 的 `ridge_layer()`）：每层山是一条随机**山脊折线**（尖峰缓谷交替）填充淡墨，再沿脊线描一笔浓墨当皴笔，最后轻度高斯模糊（3~7px，远山更大）保留笔意；远山最淡、近山最浓，层与层之间压一条模糊云雾带（`mist_band`）出留白。只叠模糊椭圆会糊成横雾，山就不成形——脊线必须有。
- 构图按画理：上 1/3 留白放标题（字落在留白处最清晰）；右上竖排题跋（诗句当题款）+「诗」印跟在字尾，不要让印章压到末字；底部可加点景（孤舟、飞鸟）。
- 出图后逐张用 vision_analyze 自查「文字有无被山/元素压住、印章有无压字」，修完再发用户。
- 画意场景元素的落地规则：结构元素必须有支撑和着落（S 初版虹桥悬在屋脊上方像浮空，下移让桥两端搭在屋脊带才成立）；装饰性小元素（柳枝、飞鸟、帆）画不好就整条删掉——形状畸形（柳枝像箭头堆）比没有更伤画面；印章永远跟在题跋末字之后且不压字，竖排题跋先算 `字数×步长` 确认不越出画布再落笔。

## 名画风格封面：定案的做法（多轮迭代后的最终共识）

- 路线演进与最终定案：①纯手绘仿名画（几何+渐变）嫌假 → ②真实扫描件「半截/立轴/金框残片」被否 → ③真画整幅铺底做过一轮后，**残片、立轴挂画彻底弃用**，但**带纱罩文字区的整幅铺底**最终被用户接受并入库（S4c 汴京长卷、U4c 工笔文房，见「封面风格库」节）——所以真图铺底不是永久禁令：关键在取景完整（主体不被裁头）、纱罩盖住文字区、繁杂处文字描边；T4c 莫高窟实景被否是取景/照片质感问题，不是「真图」本身的问题。
- 章法铁律（全部版本通用）：**左上文字区绝对干净**，任何元素不进 (x<560, y<240)——日期、大标题（44px 宋体粗，逐档缩到 ≤2 行）、副标题、栏目名都落在留白处；元素只占右侧/下部；「诗」印放画角且不压字；竖排题跋先算「字数×步长」不越画布。元素必须有支撑和着落（桥两端要落在岸/屋脊上，悬空即废）；形状画不好（畸形柳枝、箭头帆、雪人鹤）整条删掉重画，畸形比留白更伤。
- 各画种的标志元素与用户反馈：
  - **敦煌飞天（T4d，现行候选）**：土红底斑驳 + 右上**五层藻井**（方井边框 → 金环 + 24 珠串 → 红瓣环 → 金瓣环 → 绿瓣环 → 莲心花蕊；瓣用旋转椭圆叠出，不是同心圆）+ **飞天剪影绕藻井飞行**（实心画法，见下）+ 帔帛汇入右半区斜向绸带（末端卷曲）+ 卷云（沿绸带轨迹散布，起串联作用）与散花（带花瓣形）；**塔元素彻底放弃**（手绘九层楼两版都被判不像，换藻井后通过）。飞天剪影**线骨架画法不成形**（细线读不出人形，不要再用）；可行画法是**实心填充体**：粗弧躯干（先深金宽线再亮金窄线双层描边）+ 实心裙裾多边形（outline 深色勾边）+ 头部深色底圈叠亮金 + 双臂双弧线，足尖由裙尾带小弧收出（不要画棒状腿——折线腿像铁丝）；姿态选「飞向藻井、一手抚向团花」最有动势，帔帛从肩后以填充带绵延（粗端藏在身后，否则出现方形断头）。
  - **清明上河图（S4b）**：繁华密度要够才「感受得到汴京」——城楼剪影、两岸两排屋脊、酒/茶/脚/香店招旗幡、虹桥 30+ 行人小点、三艘漕船、岸柳、河面水纹。元素太稀疏被否。
  - **工笔重彩（U4b）**：牡丹被判「太女性化」，换**工笔松鹤**（老松入画、扇形松针团、侧身回首鹤：S 形颈、丹顶、橙喙、墨尾、三道弧线翼羽、立石上）。题材选择要中性。
  - **篆刻金石（V4）**：整版被否，放弃。
- **元素必须连贯成动线，不许各自孤立**：用户判定「团花和飘带、卷云看起来是分裂开的」即整版返工。正解是给出一条贯穿右上到左下的视觉动线（如飞天绕藻井飞行、帔帛垂落汇入下方绸带、卷云散花沿绸带路径散布）；散布的小元素要**沿着主元素的轨迹**放，而不是均匀撒满空白区。
- **元素密度反馈**：点缀元素（卷云、散花）被嫌少时加大数量并沿动线分布，不要只在原位放大。
- **多轮 sed/replace 改图脚本时，每处替换必须断言生效**：链式 str.replace 的锚文本若已被上一轮替换掉，会**静默不生效**，导致看似改完、元素根本没画出来。每步用 `assert old in s` 或检查返回值；插入大段代码优先用锚点定位 + 断言。
- **元素「看不见」时先局部放大排查**：把成图 `crop(区域).resize(放大)` 存盘再 vision_analyze 裁片，确认元素是否真的画出来了（整图小尺寸下细线元素不可见，容易误判成「画得不好」而反复调参）。
- **飘带用填充带、不用线条**：统一正弦公式的线状飘带被否「太规律和一致」，逐条变频的抖动线又碎成蚯蚓。正解（`cover_variant_t4d.py` 的 `ribbon()`）：沿一条平滑大弧线（二次 sag 弧）逐段取**法向偏移生成填充多边形**，宽度沿程 `w0*(0.22+0.78*sin(πt)^0.8)` 从粗到细渐变，末端补一段弧做卷曲；三条不同起点/弧度/宽度、方向斜向（如从团花下方飘向左下），才出绸帛感。
- 现成脚本：`cover_variants8.py`（T4/S4/U4 初版）→ `cover_variants9.py`（T4b/S4b/U4b 手绘修正版）→ `cover_variants10.py`（S4c 汴京长卷 / U4c 工笔文房，均入选风格库；T4c 莫高窟实景被否）→ `cover_variant_t4d.py`（T4d 敦煌飞天，入选）→ `cover_variant_s4u.py`（S4d 汴京虹桥 + U4d 工笔荷花，同一套「层叠主景+带状动线+小元素串联」语言的重做版；U4d 入选）→ `cover_variant_p3.py`（P3 富春山水，入选）→ `cover_variant_mix.py`（五个候选新主题：RH 瑞鹤图 / QL 千里江山 / WH 文会图 / XX 潇湘图 / SK 金石竹简，待用户定夺入库）。风格版式的唯一权威表是 `cover_style.py` 的 STYLES dict。
- **工笔花卉的瓣要圆不要尖**：直线多边形瓣读成雪花/烟花，点线瓣读成小帽子；正解是**沿径向旋转的椭圆瓣**（左右两条边各自生成再拼接成多边形——左右点交错 append 会折成锯齿线），两环各 6 大瓣 + 内层 5 小瓣抱心，瓣尖小椭圆染红；写实感来自「大瓣少瓣 + 层次错叠 + 勾线」而不是瓣的数量。
- **荷花/植物主景的配套动线**：落瓣带沿弧线飘散（花瓣带旋转姿态）、蜻蜓（细长身 + 四条斜翼线）、水纹弧收尾；清明上河图方向则用「酒楼檐角+酒旗 → 虹桥（拱身竖纹+栏柱+行人点）→ 漕船 → 柳枝从楼身垂下」的动线，柳枝必须挂在楼身底部而不是悬空。
- **五个新主题的画法要点**（`cover_variant_mix.py`，同套「层叠主景+带状动线+串联」语言）：
  - **瑞鹤（RH）**：石青天空由深到浅竖向渐变；鹤用实心画法——体椭圆 + **实心楔形翼面**（沿弧线两侧各取 9 点拼多边形，翼尖补墨色短弧；弧线描边的翼像把手，不要用）+ S 弧颈线 + 头部小圆 + 红顶点；一只大（s≈26）一只中（s≈21）相对飞作主景，群鹤 8px 左右伴飞；殿脊只画正脊+两端翘角+瓦垄，单侧悬出的矩形“垂檐”读成石碑。祥云用双弧卷、数量收敛在 4 组以内。
  - **千里江山（QL）**：青绿三重山共用一条规则——每个峰的高度乘以**横向位置因子** `0.38+0.62*x/W`，左低右高，否则左侧峰侵入文字区；雾带每层只压一条且 alpha≤80。文字配色对中调绿底用米白（主 242/副 222/日期 208），不要再用深墨。
  - **文会（WH）**：太湖石缩小到边长≈110px，勾边+两条透底色椭圆洞+短皴线；鳞片状弧纹会被读成鱼鳞，不要用；松枝端挂 2~3 团弧线松针簇；炉烟用填充带沿 S 弧上升做动线。
  - **潇湘（XX）**：平远远山**只画山体带（脊线以下约 34px 的闭合多边形），绝不填到画底**——三层山各自填到底会把下半幅压成灰板；下方全部留白当水面，只加疏横水纹。芦苇/雁阵/渔舟压暗色小点景。
  - **金石竹简（SK）**：深褐底+斑驳椭圆；竹简一束用圆角矩形简条+两道编绳+简面伪篆字（`seal_glyph()`：中横中竖+两側竖+底弧，细线圆转像小篆）；朱砂大方印（印面边框+2×2 伪篆四字，白文）；主景必须整体落在 x>500，竹简伸进 (x<560,y<240) 会垫在标题底下造成花底。
- **vision 缩略图会误判颜色**：淡色字在小图上被感知成深色（千里江山米白标题被连续两轮误读成深墨）。判断文字/元素颜色一律以像素为准：`Image.open(...).getpixel(坐标)` 打印实测值再决定是否改色，不要凭缩略图反复调色。

## 真实名画素材（备用，不是封面首选）
- **GitHub 全通**（api.github.com / cdn.jsdelivr.net / raw.githubusercontent.com 均可达），是名画扫描件/复刻长卷的最佳来源：用 `api.github.com/search/repositories?q=<画名>` 找开源项目，`GET /repos/<repo>/git/trees/HEAD?recursive=1` 列图片，经 `https://cdn.jsdelivr.net/gh/<repo>@HEAD/<path>` 下载。已验证素材：清明上河图风格市井长卷全景（xiwan/qingming-scroll 与 xianxie6/qingming-scroll，2172×724）、韩熙载夜宴图真迹长卷扫描（jchennyo/hanxizai）、**完整反弹琵琶飞天图**（qinnzou/mural-image-inpainting 的 `checkpoints/test/input/000740.jpg`，720×720 无标注，敦煌立轴首选）、**敦煌飞天壁画整幅（qinnzou/mural-image-inpainting 的 `other/examples.jpg`，3507×1403 多宫格示例图，第一行第 4 格橙色吹奏飞人格子 `(2108,0,2804,700)` 即为整幅无标注壁画，敦煌封面定稿用它铺底）**、莫高窟实景（gruan/MogaoCaves 的 app/img/dunhuang/1~5.jpg）、工笔文房书案（wei931125/gongbi-painting）。多宫格示例图逐格放大检查内容后再取格，不要按文件名猜。
- **Wikimedia 系全部被网络代理挡掉**（upload.wikimedia.org 与 commons api 直连和沙箱都握手超时），不要浪费时间；images.weserv.nl 代理也回 404，不可靠。
- **Pexels 纳速云镜像对中文关键词是松散标签**：搜「清明上河图」「敦煌壁画」拿到的是灯笼夜景和俄式教堂壁画，不是原画。它只适合意境配图（inline.jpg 链路），不要用于名画封面素材。
- 数据集图可能带标注残留（如裂缝检测框上的「crack」标签）：裁切元素前检查，用背景色/白色盖掉再做下一步。清理标注用**纯 PIL** 实现（云端装不上 numpy，pip 源也不可达，不要试）：青色线用 `ImageChops.subtract` 通道差值取掩膜配 `MedianFilter(19)` 大核填充，深色标签块按坐标盖底色/白块。
- 白底元素贴彩色底前，把近白像素逐像素键成底色（r,g,b > 232/228/222 判白），否则留一块生硬白框。
- 排版章法（若用户重新要求嵌入真图才用）：顶部垫**半透明纱罩**（绢色或深色，视底色）再落字，纱罩下缘 40px 渐隐过渡；**纱罩宽度必须容纳标题的折行宽度**——标题折行宽度大于纱罩时字会压到画面元素上。竖排题跋先算「字数×步长」不超过画布高，印章跟在末字后或画角，不压字。成品见 `cover_variants7.py` 的 S2 清明上河图长卷 / R2 夜宴真迹、`cover_variant_t3.py` 的 T3 立轴——三者连同残片做法均已被否，仅留技术参考。
- **不用残片/半截裁切**：把名画裁一块裱金框的做法被用户判「半截的风格太奇怪」。真图按**整幅画作全幅铺底**处理：取景窗对准画面主体，用 `crop_bias`（竖向偏移 0~1）调窗口位置——偏移不合适会裁掉人物头部，逐档试 0.08→0.3→0.15 找到主体完整的位置再定。
- **繁杂底图上的文字必须描边**（真图铺底已否，但纱罩排版技术仍适用于任何带画面的底图）：底部栏目名、竖排题跋压在画面上时必须 `stroke_width=2~3` + 深色（浅字）或绢色（深字）`stroke_fill`；纱罩高度算到**副标题底缘**而不是主标题底缘（只盖到主标题时副标题会横跨纱罩边缘，一半清晰一半糊）。取景窗还要避开「画面精华横带正好被纱罩盖住」的陷阱：精华带在画面中部时，放大原图后把窗口下移对准精华带，让纱罩只压住上方次要区域。竖排题跋先算「字数×步长」不超过画布高。

## 迭代节奏（多轮改稿的经验）

- 一轮出 3~4 版、vision_analyze 逐张自查（文字压字、元素悬空、形状畸形、印章压字四项必查）、发图带「选中后会修」清单；用户会逐版给具体意见（元素含义、密度、性别气质、裁切方式），按意见改对应元素而不是推翻重来——同一构图的修正版命名加后缀（T4→T4b）便于对话引用。
- 用户否定一个方案时会给出方向线索（「太灰暗」「太女性化」「太突兀」「半截太怪」「太丑」），把这些形容词翻译成可执行的构图规则更新进本文件，下一版直接生效。
- **否决针对当轮呈现方式，不是永久禁令**：同一个被否的素材/手法，换语境（修好取景、去掉烤死的标题、换成库化背景）后可能被接受（真图铺底从「一律不用」到 S4c/U4c 入库就是实例）。写规则时记下被否的具体成因，不要把否决升级成对整类手法的禁令。
- 用户对「含义」敏感：抽象装饰（无出处的圆、无支撑的桥）会被追问「它是什么含义」——每个元素要么有明确文化出处（藻井→九层楼），要么删掉。
